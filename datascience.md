my thought about the datascience piscine at 42

At 42 Berlin we just had a weeklong dataschiencce "piscine". In the 42 network 42 Berlin is quite unique in the sense that alreasdy twice organized a weeek long pisine where international students were also invited. there were quite a few of us including students from other campuses line abu dhabi porto madrid antwerp bruxelles. 
The way these piscines are structured is with modules of increasing difficulty. 
The first module lets us create a postgress database in a docker container and let it populate it with  data from a fictional ecommerce site. There are no teachers of course and this is the approach of 42 schools where a group of students works solo on projects following rigid quality guidelines and being evaluated by other students of the group. This is agreat way to learn. Even within the requirements of the projects there is a lot of diverse approach betweeen the students. Some of them were even already working with data or had been working in this field before. Itis a great way to learn from your peaers. also discussing the different approaches gives insights and cement the knowledge acquired. 
for instandce the files we have been given were not super big but for a total of more than a gigabyte of data in csv files there was definitely some challenges awaiting for us. 
for instance one common approach was using python to connect with the docker Postgress container. some of us used jupyter notebooks., other used a virtual python environment on their machines, some used venv and other already found out that the uv package written in rust , is a god contender to the venv virrtual environment module, because of its ease of use.
Makefile were also used to start the container and even connect to postgres command lines.
For the ones using python to create the tables there were some challenges ahead. Long processing times to import the data.   
It turns out that using the shell to connect the postgress container with the data would speed up the import considerably.
It is not always like this in production but in a development environment it is just great to rediscover the command line. Extremely fast especialyy when compined with some native postgresql commands. 
Python and the pandas framework is just really good for visualizing data in a jupyther notebook in your browaser using matplotlib for instance. Some of us used plotly and managed a 3d visualisation of the data clustering with kmeans (this was already the third module.).
the last two modules were exploring more advanced concepts like training and visualize machine learning parameters like ....
In average most of us completed 3 modules where justa handful of students managed all 5 modules. For those who did not make it through the whole thing for different reasons like (working part time for instance or other obligations) it was great to have a sneak preview of what is coming. From a pedagogic point of view this is also the right way to approach a new subject. first you get an exposure early of to new concepts and then you are coming back on a later moment to deepen your understanding. 
I did not manage to attend everyday of the piscine so i managed until the 3rd module. however I was very happy with my progress. sometimes you want to take the chance to go deeper in a topic and not just browse through, so all this low level machine learning algorithms which were implemented in the later modules deserve a better look, like forests and decision tree, I will catch up later on those even if I dont need them right now. It is also good to look under the hood, what is ai actually. Some of these techniques are from the history of AI and you might think they are used less used today, however heading to kaggle.com shows a different picture. it is always good to have a few tools in your arsenal. The takeaway, dont rely only on abstractions, observe and underastand the data, use more sql which is a very powerful language tohgether with the UNIX command line.
